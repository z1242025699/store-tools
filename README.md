# 门店 AI 工具集

零售门店里三个每天在用的工具。都不是练习项目——先在自己上班的门店里用起来，再整理出来。

**在线地址**：https://z1242025699.github.io/store-tools/

---

## 里面有什么

| 工具 | 解决什么 | 状态 |
|---|---|---|
| [临期保质计算器](calculator.html) | 输生产日期，自动算到期 / 转临期 / 下架三个日子 | 同事在用 |
| [冻品管家](assistant.html) | 40 个演示 SKU 的保质期、储存条件、临期规则问答 | 已交付 |
| [商品速查（手机版）](lookup.html) | 商品号 / 名字 / 库区秒查 | 已交付 |

---

## 三个工具的共同点

1. **单文件**。一个 `.html` 双击就能开，不用装任何东西，微信传过去也能用。
2. **不联网**。数据内嵌在文件里，不调接口——所以不会因为断网失效，也不会编造数据。
3. **手机优先**。门店里没电脑，都是在库区掏出手机看。

---

## 为什么要做成这样

门店的实际情况：

- 电脑在办公室，人在库区，来回一趟五分钟
- 网有时候不稳，不能依赖联网
- 同事不会为了一个功能装 App

所以最合适的形态是「一个能发到微信里的网页」，而不是一个系统。

---

## 做的时候踩过的坑

- **日期推算要按档位算，不能按品类**。鲜食分 1–29 天、30–89 天、90 天以上三档，每档的转临期规则不一样。
- **数据里有脏字段**。有 21 条商品的「提前天数」填的是中文「无」，直接 `parseInt` 会得到 `NaN`，日期算出来是 `NaN-NaN-NaN`。后来加了兜底判断。
- **问答规则会互相抢**。「冰淇淋柜 -20℃」这句话既能匹配"温度"，也能匹配"还能卖吗"，靠关键词打分就会答错，必须固定判定顺序。
- **交付前要全量跑数据**。全部商品每一条都要填一次日期，不能只抽样——上面那个 `NaN` 就是抽样没覆盖到才漏的。
